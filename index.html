The map for the whole case

Which layer are we talking about?

Credential security and reader-bus security are separate security problems.

A 26-bit format doesn't need a Wiegand connection; an OSDP reader can deliver 26-bit data; a DESFire EV3 chip doesn't tell you which application is on it; a reader can detect a card without the keys to its protected application; a reader can authenticate perfectly and still send data the controller decodes wrongly. Troubleshooting is stairs, not an elevator.

Layer 2 · the radio

Two radio neighborhoods

Proximity, or “Prox”

  • Sends the same static number, to anyone who asks nicely
  • Generally no modern mutual authentication
  • Often chosen for compatibility, not security
  • An easy migration target when a customer modernizes
HID ProxIndalaAWIDEM family

“Prox” is a broad legacy family. HID Prox is the best known, but Prox does not mean HID.

Prox solved convenience. It was not designed for the threat model we have today.

“The card works” and “the card is secure” are two different statements.

13.56 MHz is a street, not a house. Some houses have a bank vault. Some have a screen door.

The frequency tells you the neighborhood. It does not tell you the security model.

Don't teach RF physics. The tree is intentionally simplified. Avoid saying every 125 kHz credential is identical or that every Prox product is HID.
Layers 3 and 4

HID, from Prox to Seos

The chip is the apartment building. The application is who lives there.

Separate RF standard, credential technology, HID application and security model, and PACS output format. Legacy iCLASS should not be presented as equivalent to Seos. The SIO-on-DESFire point is a strong demonstration of the layer model.
Layer 3

What “MIFARE DESFire” actually means

MIFARE
An NXP product brand, not a company. There is no manager to speak to.
DESFire
A smart-card chip family sold under the MIFARE brand
Built on
ISO/IEC 14443A radio and standard cryptography, including AES
Model
Multi-application: independent applications can share one card

DESFire is open like a restaurant, not like a recipe. Anyone can order. Not everyone gets the kitchen.

EV1 → EV2 → EV3 is an evolution

The chip version and the application profile are separate. Real compatibility depends on:

readerapplicationkeyscommandsconfiguration
DESFire is a broadly supported secure smart-card platform, not an open-source credential. Don't teach "EV3 cards work with EV2 readers". Teach: interoperability depends on reader, application, keys, commands and configuration.
Does EV3 automatically mean more secure?

Climb the security ladder

The biggest security jump is not EV2 → EV3. It is static number → properly authenticated credential.

With mutual authentication, AES protection and good key management, an EV2 implementation can already give very strong credential security. Reading only the UID of any card is "a safe with the combination taped to the front".

Wiegand, the format

“26-bit Wiegand”, “37-bit Wiegand”: how the data is arranged into bits.

Layer 5 · PACS data format

Bits don't wear name tags

The raw bitstream doesn't say “I am H10304”. Secure Entry has to be told how to read it.

8 bits of facility code means 256 facility codes for the whole planet. Yours is unique the way your birthday is unique.

Clue 2Bits don't announce their format. Secure Entry has to be told what the CEO's 26 bits mean.
H10301 has an 8-bit facility code (0–255) and a 16-bit card number (0–65,535); nobody manages the numbering, so unrelated sites can hold identical badges. H10302 and H10304 are both 37 bits and mean different things.
Exercise · H10301

Decode the CEO's card

parityfacility code fieldcard number fieldSelect a bit to flip it. Parity is the world's smallest hall monitor.

Here are 26 bits from a card. What are the facility code and card number? (Bits 2–9 and 10–25. You can use a calculator; we won't tell.)

Ask trainees to find the parts: total length, leading parity, facility code, card number, trailing parity. Then switch to misconfigured: the reader works perfectly, the controller reads good data wrongly. Leading parity is even over bits 1–13; trailing parity is odd over bits 14–26.
Secure Entry custom card formats

Every digit right, still calling a stranger

Two readers send the same credential. Secure Entry expects 0xFB4C. Pick a reader, then fix the interpretation.

Reading the phone number right to left: every digit is correct, and you're still calling a stranger.

A custom format in Secure Entry can set

  • Bit length from 1 to 256
  • Invert bit order
  • Invert byte order, when the length divides by 8
  • Card number and facility code fields and ranges
  • Decimal or hexadecimal output
  • Big-endian or little-endian per field
The card did not change and the reader isn't necessarily broken; the problem is representation. Endianness is just which end of a value counts as most significant.
The rule that cracks the case

One chair per bit length

37 raw bits arrive, and nothing in them says which 37-bit format they are. Try seating a second one. Then play Format Roulette.

From the reader

Access control. Not a horoscope.

Don't generalize this to "no access-control system can support two formats of the same length"; some systems separate them per reader or with metadata. The Secure Entry rule is the teachable point. Field symptom: one 37-bit population works and another doesn't.

The security message

The rock outranks the reader

Attackers don't go for the strongest link. They look for the one held on with a zip tie. Select a link to break it.

One data center had guards, badge readers and logged doors out front, and a back door “propped open with a rock.” (A Hacker News commenter's story.)

A better security lesson than ranking card brands. People are a link too: holding the door is kindness, and also a bypass.

Ticket #4471 · resolved

It wasn't the card

Secure Entry event · Main entrance · 07:58:12Access denied: unknown card · 26 bits · site 675 · card 57

The causeBrightwater bought another office whose badges use a different 26-bit layout. Someone activated that format. One chair per bit length: the new format took the chair, and H10301 lost it. Fix: put H10301 back and plan the new office's migration properly.
